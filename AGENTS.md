# Инструкции по сопровождению проекта

## Документация обязательна

Документация должна соответствовать текущему состоянию проекта после каждого изменения.

Перед завершением любой задачи, меняющей файлы репозитория:

1. Проверьте, влияет ли изменение на поведение, интерфейс, архитектуру, модель данных, права доступа, конфигурацию, запуск, тестирование или развёртывание.
2. Обновите в том же наборе изменений все затронутые документы: `README.md`, `docs/ARCHITECTURE.md`, `docs/DATA_MODEL.md` и/или `docs/DEVELOPMENT.md`.
3. Если добавляется новый документ, добавьте ссылку на него в раздел «Документация» файла `README.md`.
4. Не описывайте планы как уже реализованные возможности. Документы должны описывать фактическое состояние кода.
5. В итоговом сообщении перечислите обновлённые документы либо явно укажите, что проверка выполнена и изменения документации не потребовались.

Изменение считается завершённым только после проверки актуальности документации.

## Согласованность безопасности

- При изменении операций Firestore синхронно проверяйте `firestore.rules` и `docs/DATA_MODEL.md`.
- Клиентские проверки ролей не заменяют правила Firestore.
- Новые значения, вставляемые в HTML, экранируйте через `esc`.

## Проверка

Для JavaScript запускайте `node --check app.js`, если Node.js доступен. Для всех изменений запускайте `git diff --check` и выполняйте релевантную часть дымового сценария из `docs/DEVELOPMENT.md`.
