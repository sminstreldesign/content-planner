# Контент-план

Файлы сайта готовы для GitHub Pages. Это обычный HTML/CSS/JavaScript без установки программ и `npm`.

## Что уже есть

- регистрация и вход по email;
- список своих проектов;
- создание и настройка проектов с названием, описанием и соцсетями;
- отдельный экран выбора соцсети для каждого проекта;
- рубрики, привязанные к одной или нескольким соцсетям;
- контент-план в новой вкладке: даты по вертикали, рубрики по горизонтали;
- карточка публикации с задачей, материалами, готовым текстом и визуалом;
- уникальный восьмизначный код для приглашения;
- один код проекта и персональные роли участников: читатель, комментатор, редактор, владелец;
- палитра Powder / Peanut / Stone / Pecan.

## Перед первым запуском

1. Откройте Firebase → Firestore → вкладка «Правила».
2. Замените содержимое правилами из `firestore.rules` и нажмите «Опубликовать».
3. Добавьте файлы сайта в корень репозитория GitHub: `index.html`, `styles.css`, `app.js`, `firestore.rules` и `README.md`.
4. В GitHub откройте **Settings → Pages**, выберите ветку `main` и папку `/ (root)`, затем сохраните.
5. На Firebase → Authentication → Settings → Authorized domains добавьте адрес сайта GitHub Pages после его появления.

## Как работает доступ

Новый участник вводит общий восьмизначный код проекта и получает роль читателя. Затем владелец открывает экран «Доступ» и назначает этому участнику роль комментатора или редактора. Код не определяет роль и остаётся одним для всего проекта.
