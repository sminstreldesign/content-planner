# Контент-план

Веб-приложение для совместного планирования публикаций по проектам, соцсетям и рубрикам. Пользователи создают контент-планы, собирают референсы, ведут карточки публикаций, обсуждают их в комментариях и управляют доступом команды по ролям.

Клиент написан на чистых HTML, CSS и JavaScript, хранит структурированные данные в Cloud Firestore, медиа референсов в Firebase Storage и использует Firebase Authentication. Серверные Cloud Functions формируют защищённую от клиентского редактирования историю действий. Сборщик для клиентской части не требуется.

Интерфейс использует единую природную палитру: фон `#F5F0E8`, поверхности `#FFFDF9`, основной цвет `#5D4637`, дополнительный `#88915F`, акцент `#C68B72` и текст `#342B25`. Цвета централизованы в семантических CSS-переменных в `styles.css`.

## Возможности

- публичный адаптивный лендинг с инфостильным описанием сервиса, актуальными снимками реальных экранов, объёмной SVG-версией Олли в сюжетных анимациях, интерактивной галереей и прямыми переходами ко входу и регистрации;
- регистрация и вход по email и паролю без подтверждения адреса;
- двухшаговое создание проектов с ручным добавлением площадок и рубрик;
- проектный хаб «Над чем поработаем?» с рабочими переходами во все шесть разделов, включая референсы;
- канбан-доска референсов со столбцами по соцсетям, раскрывающимися карточками, текстом «что понравилось» и загрузкой до четырёх изображений или видео по 50 МБ;
- редакторы аудита и блокнота с главами, форматированным текстом, десятью шрифтами и размерами, стилями заголовков и палитрой из двадцати цветов;
- совместный анализ целевой аудитории: до восьми сегментов, базовые группы параметров из шаблона, собственные критерии и отдельные наблюдения по каждому сегменту;
- совместный анализ до шести компаний по двенадцати самостоятельно заданным критериям со свободными заметками, оценками от 0 до 5 и автоматически обновляемой радиальной диаграммой;
- рубрики, общие для одной или нескольких соцсетей;
- назначение ответственного за соцсеть и отдельного исполнителя публикации из участников проекта;
- месячная календарная сетка с точным количеством дней и рубрик;
- карточки публикаций с задачей, текстом, цветным статусом, загрузкой до четырёх автоматически сжатых изображений и встроенным просмотром;
- комментарии к сохранённым публикациям;
- серверная история последних действий по проекту с автором и временем изменения;
- приглашение в проект по восьмизначному коду;
- роли владельца, редактора и читателя, свободное описание функции участника, изменение ролей и удаление участников владельцем;
- отдельная вкладка контент-плана для выбранной соцсети;
- адаптивная компоновка главного экрана с однострочным персональным приветствием и объёмной анимированной оливкой над списком проектов;
- адаптивная страница 404 с оригинальной SVG-иллюстрацией и CSS-анимацией.

Редакторы рубрик подсвечивают конкретные незаполненные и повторяющиеся строки, блокируют повторное сохранение во время запроса и показывают ненавязчивый прогресс. Рубрики из старых проектов без `networkIds` считаются общими для существующих соцсетей и получают актуальную привязку при следующем сохранении.

## Быстрый старт

Для локального запуска нужен любой статический HTTP-сервер. Открытие `index.html` напрямую через `file://` не рекомендуется: браузер может заблокировать ES-модули.

```powershell
python -m http.server 8000
```

После запуска откройте `http://localhost:8000`. Домен `localhost` должен быть разрешён в **Firebase Console → Authentication → Settings → Authorized domains**.

Конфигурация клиентского Firebase-проекта находится в `app.js`. Перед использованием другого Firebase-проекта замените `firebaseConfig`, включите вход по Email/Password, создайте Cloud Firestore и Firebase Storage, затем опубликуйте правила из `firestore.rules` и `storage.rules`. Приложение не отправляет письма подтверждения: авторизованный пользователь получает доступ сразу после регистрации, а доступ к проектам по-прежнему ограничивается memberships и ролями.

Для истории действий требуются Node.js 22, Firebase CLI и развёртывание каталога `functions/`. Cloud Functions доступны на тарифе Firebase Blaze; для проекта следует настроить бюджетные уведомления. Без развёрнутых функций остальное приложение продолжит работать, но новые записи истории создаваться не будут. Сжатые изображения публикаций остаются в Firestore, а исходные изображения и видео доски референсов загружаются в Firebase Storage.

## Развёртывание

Проект можно публиковать как статический сайт, в том числе через GitHub Pages:

1. Разместите файлы репозитория в ветке публикации.
2. В GitHub откройте **Settings → Pages**.
3. Выберите нужную ветку и каталог `/ (root)`.
4. Добавьте полученный домен Pages в список Authorized domains в Firebase Authentication.
5. Переведите Firebase-проект на тариф Blaze, если история действий ещё не развёрнута, и настройте бюджетные уведомления.
6. Установите зависимости функций командой `npm --prefix functions install`.
7. Опубликуйте функции и правила: `firebase deploy --only functions,firestore:rules,storage --project <project-id>`.

Firebase API key в браузерном приложении не является серверным секретом. Доступ к данным должен оставаться защищён правилами Firestore и настройками Authentication.

## Структура проекта

```text
.
├── index.html          # оболочка приложения
├── 404.html            # страница для несуществующих адресов
├── favicon.svg         # логотип CP для вкладки браузера
├── assets/             # реальные продуктовые снимки для публичного лендинга
├── styles.css          # стили и адаптивная вёрстка
├── app.js              # интерфейс, состояние и работа с Firebase
├── firestore.rules     # серверные правила доступа к данным
├── storage.rules       # серверные правила доступа к медиа референсов
├── firebase.json       # конфигурация правил и Cloud Functions для Firebase CLI
├── functions/          # серверные триггеры защищённой истории действий
├── docs/
│   ├── ARCHITECTURE.md # устройство приложения и основные сценарии
│   ├── DATA_MODEL.md   # коллекции, поля и матрица прав
│   └── DEVELOPMENT.md  # локальная разработка и проверка изменений
└── AGENTS.md           # правила сопровождения репозитория
```

## Текущие ограничения

- автоматические тесты и CI пока не настроены;
- все экраны находятся в одном JavaScript-модуле;
- удаление соцсети или рубрики не выполняет каскадную очистку связанных публикаций;
- публикации и комментарии загружаются целиком для выбранного проекта или плана, без пагинации и real-time подписок;
- экран истории показывает последние 100 событий, не обновляется в реальном времени и не восстанавливает действия до первого развёртывания функций;
- дата начала календаря задаётся при создании проекта и сейчас не редактируется через интерфейс;
- доска референсов загружается целиком и не поддерживает перетаскивание карточек между столбцами;
- форматированный текст аудита и блокнота хранится целиком в одном документе каждого типа и не поддерживает совместное редактирование в реальном времени.
