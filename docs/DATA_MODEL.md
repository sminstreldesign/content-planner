# Модель данных и права доступа

Источник истины для серверных разрешений — файл `firestore.rules`, опубликованный в Cloud Firestore. Клиентские проверки ролей в `app.js` только скрывают недоступные действия в интерфейсе.

## Коллекции

### `profiles/{userId}`

Профиль создаётся при регистрации.

| Поле | Тип | Назначение |
| --- | --- | --- |
| `name` | string | отображаемое имя |
| `email` | string | email пользователя |
| `createdAt` | timestamp | время регистрации |

Пользователь может создать собственный профиль сразу после регистрации, чтобы завершить создание аккаунта. Чтение и изменение профиля, как и доступ к остальным данным приложения, разрешены только после подтверждения email. Удаление запрещено правилами.

### `projects/{projectId}`

| Поле | Тип | Назначение |
| --- | --- | --- |
| `ownerId` | string | UID создателя |
| `name` | string | название проекта |
| `description` | string | описание проекта |
| `shareCode` | string | текущий восьмизначный код приглашения |
| `planStartDate` | string | начальная дата плана в формате `YYYY-MM-DD` |
| `createdAt` | timestamp | время создания |
| `updatedAt` | timestamp | время последнего изменения, если применимо |

Под документом проекта находятся пять подколлекций.

#### `projects/{projectId}/networks/{networkId}`

| Поле | Тип | Назначение |
| --- | --- | --- |
| `name` | string | название площадки |
| `createdAt` | timestamp | время создания |

#### `projects/{projectId}/rubrics/{rubricId}`

| Поле | Тип | Назначение |
| --- | --- | --- |
| `name` | string | название рубрики |
| `networkIds` | string[] | площадки, где применяется рубрика |
| `createdAt` | timestamp | время создания |
| `updatedAt` | timestamp | время изменения |

У документов ранней версии поле `networkIds` может отсутствовать. Клиент трактует такую рубрику как общую для всех существующих соцсетей проекта и записывает явный массив при следующем сохранении. Пустой массив означает, что рубрика не назначена ни одной соцсети; актуальный интерфейс подсвечивает такое состояние и не отправляет форму.

#### `projects/{projectId}/posts/{postId}`

| Поле | Тип | Назначение |
| --- | --- | --- |
| `networkId` | string | идентификатор площадки |
| `networkName` | string | снимок названия площадки |
| `rubricId` | string | идентификатор рубрики |
| `rubricName` | string | снимок названия рубрики |
| `date` | string | дата публикации `YYYY-MM-DD` |
| `title` | string | название публикации |
| `idea` | string | суть публикации |
| `benefit` | string | польза для аудитории |
| `format` | string | формат материала |
| `caption` | string | готовый текст или подводка |
| `status` | string | один из статусов приложения |
| `authorId` | string | UID автора, задаётся при создании |
| `createdAt` | timestamp | время создания |
| `updatedAt` | timestamp | время изменения |

Текущие статусы: `Идея`, `В работе`, `На согласовании`, `Готово`, `Опубликовано`.

Старые строковые поля `reference`, `visual`, `referenceImages` и `visualImages` не создаются новой версией интерфейса. Безопасные HTTPS- и `data:image`-значения из них могут отображаться для обратной совместимости.

#### `projects/{projectId}/postImages/{imageId}`

Сжатые изображения публикаций хранятся отдельно от документа публикации. Клиент принимает файл до 20 МБ, уменьшает его до 1400 пикселей по большей стороне, кодирует в WebP и старается получить размер не более 90 КБ. На одну публикацию интерфейс разрешает до четырёх изображений.

| Поле | Тип | Назначение |
| --- | --- | --- |
| `postId` | string | идентификатор публикации |
| `kind` | string | `reference` для референса или `visual` для готового визуала |
| `dataUrl` | string | изображение WebP в формате Data URL, не более 140 000 символов по правилам |
| `authorId` | string | UID пользователя, загрузившего изображение |
| `createdAt` | timestamp | время создания |

Участники проекта могут читать изображения. Владелец и редактор могут создавать и удалять их. Обновление существующего документа изображения запрещено: замена выполняется удалением и новой загрузкой.

#### `projects/{projectId}/comments/{commentId}`

| Поле | Тип | Назначение |
| --- | --- | --- |
| `postId` | string | публикация, к которой относится комментарий |
| `authorId` | string | UID автора |
| `authorName` | string | снимок имени автора |
| `text` | string | текст комментария |
| `createdAt` | timestamp | время создания |

### `memberships/{projectId}_{userId}`

Membership связывает пользователя с проектом и является основанием для доступа.

| Поле | Тип | Назначение |
| --- | --- | --- |
| `projectId` | string | идентификатор проекта |
| `userId` | string | UID участника |
| `role` | string | `owner`, `editor` или `viewer` |
| `inviteCode` | string | код входа; присутствует у приглашённых участников |
| `userName` | string | снимок имени для списка участников |
| `userEmail` | string | снимок email для списка участников |
| `joinedAt` | timestamp | время присоединения |

Наличие membership недостаточно для чтения данных: опубликованные правила также требуют `request.auth.token.email_verified == true`. Исключение — создание собственного документа `profiles/{uid}` непосредственно после регистрации, до перехода по ссылке из письма.

Предсказуемый ID позволяет напрямую проверить membership для пары проект–пользователь. Владелец создаётся без `inviteCode`.

В существующих данных может встречаться устаревшее значение `commenter`. Клиент трактует его как `viewer`, а экран доступа владельца автоматически сохраняет для такого участника роль `viewer`. До миграции правила разрешают устаревшей роли только чтение.

### `invitations/{code}`

ID документа — восьмизначный цифровой код.

| Поле | Тип | Назначение |
| --- | --- | --- |
| `projectId` | string | проект приглашения |
| `role` | string | начальная роль, сейчас всегда `viewer` |
| `active` | boolean | действует ли код |
| `createdAt` | timestamp | время первоначального создания |
| `updatedAt` | timestamp | время повторной записи кода |

## Матрица ролей

| Действие | Владелец | Редактор | Читатель |
| --- | :---: | :---: | :---: |
| Читать проект, площадки, рубрики, публикации, изображения и комментарии | ✓ | ✓ | ✓ |
| Изменять настройки или удалить проект | ✓ | — | — |
| Создавать, менять и удалять площадки | ✓ | ✓ | — |
| Создавать, менять и удалять рубрики | ✓ | ✓ | — |
| Создавать, менять и удалять публикации и их изображения | ✓ | ✓ | — |
| Создавать комментарии | ✓ | ✓ | — |
| Менять или удалять любые комментарии по правилам | ✓ | — | — |
| Видеть полный список участников | ✓ | — | — |
| Менять роли других участников | ✓ | — | — |
| Удалять других участников из проекта | ✓ | — | — |
| Управлять кодом приглашения | ✓ | — | — |

Интерфейс сейчас не предоставляет изменение и удаление комментариев. По правилам удалять или изменять комментарии может только владелец; редактор может создавать комментарии, но не может затем изменить или удалить собственный комментарий.

## Инварианты доступа

- проект создаёт только его будущий владелец (`ownerId == request.auth.uid`);
- новый участник по действующему коду всегда получает роль `viewer`;
- только владелец назначает роли `viewer` и `editor` и удаляет memberships других участников;
- роль владельца нельзя передать или изменить через текущие правила;
- invitation можно прочитать по известному коду, но нельзя получить списком;
- удаление проекта выполняется клиентом вручную: клиент сначала проверяет чтение всех подколлекций, затем удаляет подколлекции и связанные документы, сам проект и membership владельца;
- правила для `postImages` должны быть опубликованы в Firebase до использования загрузки или удаления изображений; публикация сайта через GitHub Pages правила Firestore не обновляет.

При добавлении коллекции или поля обновите этот документ и `firestore.rules` в одном изменении. При изменении роли обновите также клиентские проверки `canEdit`/`canComment` и матрицу выше.
