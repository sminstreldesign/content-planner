# Модель данных и права доступа

Источник истины для серверных разрешений — файл `firestore.rules`, опубликованный в Cloud Firestore. Клиентские проверки ролей в `app.js` только скрывают недоступные действия в интерфейсе.

## Коллекции

### `profiles/{userId}`

Профиль создаётся при регистрации.

| Поле | Тип | Назначение |
| --- | --- | --- |
| `name` | string | отображаемое имя |
| `email` | string | email пользователя |
| `createdAt` | timestamp | время регистрации |

Пользователь может создать, прочитать и изменить только собственный профиль при действующей сессии Firebase Authentication. Удаление запрещено правилами.

### `projects/{projectId}`

| Поле | Тип | Назначение |
| --- | --- | --- |
| `ownerId` | string | UID создателя |
| `name` | string | название проекта |
| `description` | string | описание проекта |
| `shareCode` | string | текущий восьмизначный код приглашения |
| `planStartDate` | string | начальная дата плана в формате `YYYY-MM-DD` |
| `createdAt` | timestamp | время создания |
| `updatedAt` | timestamp | время последнего изменения, если применимо |
| `deletingAt` | timestamp | временная метка клиентского каскадного удаления; в обычном состоянии отсутствует |

Под документом проекта находятся семь подколлекций.

#### `projects/{projectId}/networks/{networkId}`

| Поле | Тип | Назначение |
| --- | --- | --- |
| `name` | string | название площадки |
| `assigneeId` | string | UID ответственного участника или пустая строка |
| `assigneeName` | string | снимок имени ответственного или пустая строка |
| `createdAt` | timestamp | время создания |
| `updatedAt` | timestamp | время изменения ответственного, если применимо |

Поля ответственного отсутствуют у старых документов и добавляются при первом выборе. Назначать ответственного могут владелец и редактор. Имя хранится снимком, поэтому остаётся читаемым после удаления участника из проекта.

#### `projects/{projectId}/rubrics/{rubricId}`

| Поле | Тип | Назначение |
| --- | --- | --- |
| `name` | string | название рубрики |
| `networkIds` | string[] | площадки, где применяется рубрика |
| `createdAt` | timestamp | время создания |
| `updatedAt` | timestamp | время изменения |

У документов ранней версии поле `networkIds` может отсутствовать. Клиент трактует такую рубрику как общую для всех существующих соцсетей проекта и записывает явный массив при следующем сохранении. Пустой массив означает, что рубрика не назначена ни одной соцсети; актуальный интерфейс подсвечивает такое состояние и не отправляет форму.

#### `projects/{projectId}/posts/{postId}`

| Поле | Тип | Назначение |
| --- | --- | --- |
| `networkId` | string | идентификатор площадки |
| `networkName` | string | снимок названия площадки |
| `rubricId` | string | идентификатор рубрики |
| `rubricName` | string | снимок названия рубрики |
| `date` | string | дата публикации `YYYY-MM-DD` |
| `title` | string | название публикации |
| `idea` | string | суть публикации |
| `benefit` | string | польза для аудитории |
| `format` | string | формат материала |
| `caption` | string | готовый текст или подводка |
| `status` | string | один из статусов приложения |
| `assigneeId` | string | UID исполнителя или пустая строка |
| `assigneeName` | string | снимок имени исполнителя или пустая строка |
| `authorId` | string | UID автора, задаётся при создании |
| `createdAt` | timestamp | время создания |
| `updatedAt` | timestamp | время изменения |

Текущие статусы: `Идея`, `В работе`, `На согласовании`, `Готово`, `Опубликовано`.

При открытии новой публикации и старой публикации без полей назначения интерфейс выбирает текущего ответственного соцсети. После сохранения назначение становится самостоятельным: последующая смена ответственного соцсети его не меняет. Можно явно сохранить публикацию без исполнителя. Снимок имени позволяет показать прежнего исполнителя после удаления его membership.

Старые строковые поля `reference`, `visual`, `referenceImages` и `visualImages` не создаются новой версией интерфейса. Безопасные HTTPS- и `data:image`-значения из них могут отображаться для обратной совместимости.

#### `projects/{projectId}/postImages/{imageId}`

Сжатые изображения публикаций хранятся отдельно от документа публикации. Клиент принимает файл до 20 МБ, уменьшает его до 1400 пикселей по большей стороне, кодирует в WebP и старается получить размер не более 90 КБ. На одну публикацию интерфейс разрешает до четырёх изображений.

| Поле | Тип | Назначение |
| --- | --- | --- |
| `postId` | string | идентификатор публикации |
| `kind` | string | `reference` для референса или `visual` для готового визуала |
| `dataUrl` | string | изображение WebP в формате Data URL, не более 140 000 символов по правилам |
| `authorId` | string | UID пользователя, загрузившего изображение |
| `createdAt` | timestamp | время создания |

Участники проекта могут читать изображения. Владелец и редактор могут создавать и удалять их. Обновление существующего документа изображения запрещено: замена выполняется удалением и новой загрузкой.

#### `projects/{projectId}/comments/{commentId}`

| Поле | Тип | Назначение |
| --- | --- | --- |
| `postId` | string | публикация, к которой относится комментарий |
| `authorId` | string | UID автора |
| `authorName` | string | снимок имени автора |
| `text` | string | текст комментария |
| `createdAt` | timestamp | время создания |

#### `projects/{projectId}/competitorAnalyses/main`

Единственный документ сравнения конкурентов проекта. Фиксированный ID `main` не допускает появления параллельных версий анализа. Интерфейс хранит до шести компаний и двенадцати критериев; свободные заметки ограничены 1000 символами на ячейку.

| Поле | Тип | Назначение |
| --- | --- | --- |
| `companies` | map[] | упорядоченный список компаний с полями `id` и `name` |
| `criteria` | map[] | упорядоченный список критериев с `id`, `name`, картой заметок `notes` и картой целых оценок `scores` от 0 до 5; ключи карт — ID компаний |
| `updatedBy` | string | UID пользователя, выполнившего последнее сохранение |
| `createdAt` | timestamp | время первого сохранения |
| `updatedAt` | timestamp | время последнего сохранения |

Владелец и редактор создают и изменяют документ; читатель получает только чтение. Правила проверяют фиксированный ID документа, роль, допустимое число компаний и критериев и служебные поля. Полное содержимое вложенных массивов нормализуется клиентом; пользовательские строки при выводе проходят через `esc`. Удаление документа разрешено владельцу только во время каскадного удаления проекта после установки `deletingAt`.

#### `projects/{projectId}/activity/{eventHash}`

Серверный журнал действий. ID документа — SHA-256 идентификатора исходного CloudEvent; повторная доставка одного события перезаписывает ту же запись и не создаёт дубликат.

| Поле | Тип | Назначение |
| --- | --- | --- |
| `actorId` | string | UID пользователя из auth context или пустая строка для системного события |
| `actorName` | string | снимок отображаемого имени на момент обработки события |
| `action` | string | `create`, `update` или `delete` |
| `entityType` | string | `project`, `network`, `rubric`, `post`, `image`, `comment`, `competitorAnalysis` или `member` |
| `entityId` | string | ID изменённого документа или UID участника |
| `entityName` | string | короткий снимок названия сущности |
| `summary` | string | читаемое описание действия без полного содержимого публикации |
| `changedFields` | string[] | изменённые значимые поля; для создания и удаления пустой массив |
| `createdAt` | timestamp | время исходного CloudEvent |

Записи создаёт только Firebase Admin SDK внутри Cloud Functions. Клиентам запрещено создание и изменение. Все участники проекта могут читать журнал. Владелец может удалить записи только после установки `deletingAt` в рамках удаления всего проекта. История начинает накапливаться после развёртывания функций и не содержит полных версий редактируемых текстов.

### `memberships/{projectId}_{userId}`

Membership связывает пользователя с проектом и является основанием для доступа.

| Поле | Тип | Назначение |
| --- | --- | --- |
| `projectId` | string | идентификатор проекта |
| `userId` | string | UID участника |
| `role` | string | `owner`, `editor` или `viewer` |
| `inviteCode` | string | код входа; присутствует у приглашённых участников |
| `userName` | string | снимок имени для списка участников |
| `userEmail` | string | снимок email для списка участников |
| `specialty` | string | свободное описание функции в проекте, не более 100 символов |
| `joinedAt` | timestamp | время присоединения |

Для доступа требуется действующая сессия Firebase Authentication. Доступ к данным конкретного проекта определяется membership и ролью; подтверждение email правилами не проверяется.

Предсказуемый ID позволяет напрямую проверить membership для пары проект–пользователь. Владелец создаётся без `inviteCode`. Владелец и редактор читают memberships своей команды для выбора ответственного; читатель читает только собственный membership, а внешний пользователь и участник другого проекта не получают список. Поле `specialty` может отсутствовать в старых документах и редактируется владельцем свободным текстом, в том числе для его собственного membership.

В существующих данных может встречаться устаревшее значение `commenter`. Клиент трактует его как `viewer`, а экран доступа владельца автоматически сохраняет для такого участника роль `viewer`. До миграции правила разрешают устаревшей роли только чтение.

### `invitations/{code}`

ID документа — восьмизначный цифровой код.

| Поле | Тип | Назначение |
| --- | --- | --- |
| `projectId` | string | проект приглашения |
| `role` | string | начальная роль, сейчас всегда `viewer` |
| `active` | boolean | действует ли код |
| `createdAt` | timestamp | время первоначального создания |
| `updatedAt` | timestamp | время повторной записи кода |

## Матрица ролей

| Действие | Владелец | Редактор | Читатель |
| --- | :---: | :---: | :---: |
| Читать проект, площадки, рубрики, публикации, изображения, комментарии, анализ конкурентов и историю | ✓ | ✓ | ✓ |
| Создавать или изменять записи истории с клиента | — | — | — |
| Изменять настройки или удалить проект | ✓ | — | — |
| Создавать, менять и удалять площадки | ✓ | ✓ | — |
| Создавать, менять и удалять рубрики | ✓ | ✓ | — |
| Создавать, менять и удалять публикации и их изображения | ✓ | ✓ | — |
| Создавать комментарии | ✓ | ✓ | — |
| Создавать и изменять анализ конкурентов | ✓ | ✓ | — |
| Менять или удалять любые комментарии по правилам | ✓ | — | — |
| Видеть полный список участников для выбора ответственного | ✓ | ✓ | — |
| Менять свободное описание функции участника | ✓ | — | — |
| Менять роли других участников | ✓ | — | — |
| Удалять других участников из проекта | ✓ | — | — |
| Управлять кодом приглашения | ✓ | — | — |

Интерфейс сейчас не предоставляет изменение и удаление комментариев. По правилам удалять или изменять комментарии может только владелец; редактор может создавать комментарии, но не может затем изменить или удалить собственный комментарий.

## Инварианты доступа

- проект создаёт только его будущий владелец (`ownerId == request.auth.uid`);
- новый участник по действующему коду всегда получает роль `viewer`;
- новое или изменённое непустое назначение ответственного должно ссылаться на существующий membership этого проекта; неизменённый снимок удалённого участника может сохраняться в старом документе;
- только владелец назначает роли `viewer` и `editor` и удаляет memberships других участников;
- роль владельца нельзя передать или изменить через текущие правила;
- invitation можно прочитать по известному коду, но нельзя получить списком;
- удаление проекта выполняется клиентом вручную: клиент устанавливает `deletingAt`, проверяет чтение всех подколлекций, удаляет в том числе анализ конкурентов и историю, связанные документы, сам проект и membership владельца;
- Cloud Functions записывают историю через Admin SDK, а повторная доставка одного CloudEvent не создаёт дубликат;
- правила для `postImages` должны быть опубликованы в Firebase до использования загрузки или удаления изображений; публикация сайта через GitHub Pages правила Firestore не обновляет.

При добавлении коллекции или поля обновите этот документ и `firestore.rules` в одном изменении. При изменении роли обновите также клиентские проверки `canEdit`/`canComment` и матрицу выше.
